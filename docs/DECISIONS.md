**C-001 · Git branch** — The cloud harness started the session on `claude/nice-turing-2470ze`; the brief (D10) and kickoff prompt say work on `main`. Decision: work on `main` (identical commit at start) and push there; if `main` pushes are rejected, push the session branch and note it in STATUS.md. Why: the owner's explicit instruction in the kickoff prompt.

**C-002 · Model fetching** — Context: BRIEF §13 wants pinned, verified, resumable, per-group downloads. Alternatives: pure-bash TOML parsing; a Rust xtask; Python stdlib helper. Decision: `scripts/fetch-models.sh` → `scripts/fetch_models.py` (stdlib only, `curl -C -` for resume, `tomllib`, SHA-256 + size verification). Why: Python 3.11+ is on both the cloud VM and the Mac; no extra deps; bash TOML parsing is brittle. Whisper/VAD/eval hashes were taken from HF LFS metadata of the pinned revision and are re-verified on every download; PocketTTS hashes match BRIEF §3.2 exactly (all 12 files verified).

**C-003 · FLEURS subset** — Context: FLEURS parquet files are 400–800 MB per language with a single row group. Decision: `scripts/fleurs_subset.py` reads the pinned parquet through `HfFileSystem` range reads and extracts 10 utterances (5–20 s) per language; ≈ 7 min total, nothing large stored. FLEURS is generated, never committed (CC-BY-4.0 attribution in About later).

**C-004 · TTS parity test-set budget (cloud, 4 vCPU)** — Context: BRIEF §6.1 asks for all 10 voices on short+medium texts, 3 samples per (text, voice), long text on 3 voices; the reference runs at RTF ≈ 1.2 on this VM. Decision: 11 short/medium/special texts + 1 long text (1 457 words, ≈ 8–9 min of audio; BRIEF says ~1500). All 10 voices × 3 samples on s1,s2,m1,m2; george/alba/michael × 3 samples on s3,s4,m3,m4,n1,q1,l1; the long text on george/alba/michael × **1** sample (3 samples would add ≈ 3 h per engine). Bulk WER ASR is Whisper `small` (turbo ≈ 36 s per 30 s window on this CPU would make 400+ clips take > 4 h); a turbo cross-check on a subset is added where time allows. Gates are relative so the ASR choice cancels; this is noted in the report.

**C-005 · Candle PocketTTS port — what the 2.1.0 weights required** — Context: the `pocket-tts` 0.6.2 crate (babybirdprd, MIT OR Apache-2.0) targets the older `b6369a24` model. Findings: (1) the 2.1.0 `english` weights have `inner_dim=32` in Mimi's downsample and `speaker_proj_weight [1024,32]`; (2) the ten voice files are **serialized KV-cache model states** (`transformer.layers.N.self_attn/cache` `[2,1,T,16,64]` + `offset`), not `audio_prompt` latents; (3) the crate's text chunking/padding differs from Python 2.1.0 (`split_into_best_sentences` is token-boundary based, no 8-space padding for `english`, `max_gen_len = ceil((tokens/3+2)·12.5)`, `frames_after_eos = guess+2`); (4) the crate drags in `hf-hub`, `intel-mkl-src`, `tokenizers/http` (network-capable). Decision: vendor + patch (`spike/tts-rust/vendor/pocket-tts`, PATCHES in its README): local-path-only weights, KV voice-state loader, inner_dim support, Python-faithful chunker (verified identical chunks on all test texts incl. the 62-chunk long text), no hf-hub/MKL. Speed: the crate decodes Mimi serially (RTF 1.5); the Python reference overlaps decode in a thread, so the Candle path now pipelines flow-LM and Mimi on two threads (RTF 1.0 vs reference 1.2 on this VM).

**C-006 · Audio decode stack** — symphonia 0.6.1 (all codecs/formats) + `symphonia-adapter-opus-rs` (pure-Rust Opus, no libopus/cmake) + own MP4 `elst` reader (symphonia's isomp4 is not gapless: AAC priming leaked +46 ms). All 21 fixture formats decode within ±50 ms of the source and match its content (lossless: correlation ≥ 0.99). **MKV/AAC** gets ±100 ms because Matroska carries no AAC priming/padding info (unknowable by any decoder; documented in the test). AVFoundation fallback stays a Mac item.

**C-007 · Recorder design** — One SPSC ring per stream session (a rebuilt stream gets a fresh ring; the writer drains the old one first, so no samples are lost at the switch). Pause closes the stream (mic indicator goes off, no samples buffered). Default-device following polls `AudioInput::default_device_id()` once per second *only while recording* (cpal 0.18 itself auto-reroutes default-device streams and reports `ErrorKind::DeviceChanged`; the Mac session must verify that the two don't fight — MAC_HANDOFF #4). File format fixed to the first device's rate; later devices are resampled (rubato). WAV header is patched in place + fsync every 2 s (`sync_interval`), measured loss on `kill -9`: 1.2 s. Recordings >≈4 GB (≈ 12 h at 48 kHz) stop gracefully (classic RIFF limit) — RF64 left for "Later".
